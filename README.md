# Simple Attention Architecture: a Fixed-Point Scaled Dot-Product Attention Accelerator in Verilog

- **Author:** Md. Rakib Rayhan, Dept. of ECE, North South University
- **Task:** ARCH Lab (UMass Amherst) – *Simple Attention Architecture*
- **Simulator:** Icarus Verilog 12 (lint-clean in Verilator with `-Wno-WIDTH`)

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √dₖ ) · V ,   Q = X·W_Q,  K = X·W_K,  V = X·W_V
```

A sequential, single-multiplier accelerator that computes one attention head entirely in fixed-point arithmetic. It uses a base-2 LUT exponential and a one-reciprocal-per-row softmax. The RTL is verified **bit-exact** against a Python model of the hardware at every stage (Q, K, V, scores, weights, output), and its accuracy is measured against floating-point NumPy.

| | |
|---|---|
| Multipliers | **1** × 18×18 signed (one Cyclone IV embedded multiplier) |
| Number format | Q8.8 signed data · Q0.16 softmax weights · 48-bit accumulator |
| Softmax | max-subtraction → 2^x via 64-entry LUT + shift → 1 reciprocal/row (restoring divider) → multiply |
| Score memory | **O(N)**: row-streaming, only one score row is stored |
| Accuracy | ≤ 1.5 LSB (≤ 0.006) max error vs. float on typical data |
| MAC utilization | 97.7 % (N = 16, dₖ = 64) |
| Verification | 2 unit testbenches + 5 system tests, all **bit-exact** to the reference model |

## 1. Quick start

Requirements: Icarus Verilog (≥ 11), Python 3 with NumPy, and optionally GTKWave.

```bash
python scripts/run_all.py              # full regression: generate → unit tests → 5 system tests → check
```
Expected final line: `== OVERALL: PASS`. The results table is written to `results/summary.md`.

Run and inspect a single test:
```bash
python scripts/run_sim.py hand2        # compile + simulate  → tests/hand2/output.txt, attention.vcd
python scripts/check.py  hand2         # bit-exact + accuracy + latency check
gtkwave tests/hand2/attention.vcd
```

```bash

```

## 2. Repository layout

## 3. File formats

| File | Format |
|---|---|
| `tests/<name>/inputs/{x,wq,wk,wv}.txt` | **Human-editable input.** Decimal, one matrix row per line, space-separated (e.g. `0.5 0 0.5 0`). X is N×D; W_Q, W_K and W_V are D×dₖ. |
| `tests/<name>/{x,wq,wk,wv}.hex` | **Simulator input**, read with `$readmemh`. One 16-bit two's-complement Q8.8 word per line, 4 hex digits, row-major (`0100` = 1.0, `ff80` = −0.5). Generated from the `.txt` files by `gen_tests.py`. |
| `params.txt` | `N D DK` |
| `output.hex` / `output.txt` | **Simulator output.** O (N×dₖ) in hex Q8.8 and in decimal. |
| `hw_{q,k,v,s,a}.hex` | Intermediate buffers dumped by the testbench (weights `a` are unsigned Q0.16). |
| `expected_*.hex`, `expected_float.txt` | Bit-exact model output and float reference. |
| `attention.vcd` | Waveform (pass `+novcd` to skip it for large tests). |

To add a test, create `tests/<name>/inputs/*.txt`, add `build("<name>")` to `model/gen_tests.py`, and run `run_all.py`.

## 4. Architecture

```
            load port (ld_en / ld_sel / ld_addr / ld_data)
                 │
     ┌───────────▼────────────┐
     │ X, W_Q, W_K, W_V bufs   │
     └───────────┬────────────┘
                 │            ┌──────────── Q / K / V buffers (N×dₖ)
                 ▼            ▼                       │
          ┌──────────────────────────┐                │
          │ Operand MUX (data fetch)  │◄── s_row, a_row (one row each)
          └─────────────┬────────────┘                │
                        ▼                             │
                ┌──────────────┐  acc (48 b)  ┌──────────────┐
                │ MAC 18×18     ├─────────────►│ round_sat    ├──► Q/K/V, s_row, O
                └──────────────┘     │        └──────────────┘
                                     ├──► exp2_unit (LUT + shift) ──► a_row, Σ
                                     └──► w = e·R >> 16          ──► a_row
          Σ ──► recip_div (2³² / Σ) ──► R
          ┌──────────────────────────────┐
          │ Control FSM (14 states)       │ ──► drives every mux, enable and write
          └──────────────────────────────┘
```

Relation to the reference block diagram: the *Matrix Multiply Engine*, *Attention Score Unit* and *Output MAC Unit* are one time-shared MAC. The *Scaling Unit* is folded into the rounding shift. The *Normalization Unit* is `exp2_unit` + `recip_div` + two MAC states.

### Dataflow and FSM
```
IDLE ─start─► PROJ_MAC ⇄ PROJ_WR            Q, K, V = X·W   (3·N·dₖ dot products of length D)
              │  for each query row i  (row streaming):
              ├► SCORE_MAC ⇄ SCORE_WR       s_j = Q_i·K_j >>> (8 + log₂√dₖ),  running max
              ├► EXP_MUL   ⇄ EXP_WR         e_j = 2^(−(max − s_j)·log₂e),     running sum
              ├► DIV_START → DIV_WAIT       R = ⌊2³² / Σe⌋                   (34 cycles)
              ├► NORM_MUL  ⇄ NORM_WR        w_j = e_j·R >> 16                 (Q0.16)
              └► OUT_MAC   ⇄ OUT_WR         O_i = Σ_k w_k·V_k >>> 16  ──► next row / DONE
```
Each `*_MAC` state issues one product per clock, and `clr = (k == 0)` starts a new sum with no idle cycle. Each `*_WR` state rounds, saturates and stores the result and then advances the loop counters.

## 5. Design decisions and justification

| Decision | Choice | Justification |
|---|---|---|
| Sequential vs. parallel | **Sequential, 1 MAC** | Minimal area (1 DSP) and a single datapath that is easy to verify. Utilization is 97.7 %, so the multiplier is the true bottleneck and throughput scales directly with the number of MACs (see §8). |
| Pipelining | **Not pipelined** (single-cycle MAC) | It keeps the FSM simple and makes the latency formula exact. The next step would be a registered product (2-stage MAC) to raise Fmax. |
| Representation | **Fixed point** | Floating-point exp/div/add units are many times larger. Attention values in small models fit comfortably in Q8.8, and the measured error is ≤ 1.5 LSB. |
| Bit widths | Q8.8 data (range ±128, step 1/256). Q0.16 weights (always in [0,1], so all bits are fraction). 18-bit multiplier operands. 48-bit accumulator. | 18×18 is the native Cyclone IV multiplier, so 18-bit operands are free and let the same MAC handle unsigned 16-bit weights. With 34-bit products, 48 bits can accumulate up to 16 k terms without overflow. Rounding is half-up (no −½ LSB bias). Results saturate instead of wrapping. |
| 1/√dₖ scaling | **Arithmetic shift**, merged into the score rounding (`>>> 8 + log₂√dₖ`) | Zero hardware and no double rounding. It requires dₖ ∈ {4, 16, 64, …}, which includes the common dₖ = 64. Other dₖ would need one constant multiply. |
| Softmax | Max-subtraction + base-2 exp (LUT + shift) + **one reciprocal per row** | See §6. |
| Memory | **Row streaming:** the score and weight buffers hold one row | O(N) instead of O(N²) score storage, the same idea that makes FlashAttention memory-efficient. The row max and sum are tracked on the fly. |

## 6. Softmax implementation

For one row of scaled scores s₀ … s_{N−1}:

1. **Max subtraction:** dⱼ = sⱼ − max(s) ≤ 0. Since softmax(x) = softmax(x − c), the result is unchanged. Every eᵈ ≤ 1, so the exponentials fit in Q0.16 and cannot overflow.
2. **Base change:** eᵈ = 2^(−u) with u = (−d)·log₂e. This takes one MAC cycle with the constant 94548 (log₂e in Q.16), and u is in Q8.8.
3. **2^(−u) = 2^(−⌊u⌋) · 2^(−frac(u))**
   - 2^(−frac(u)): a 64-entry ROM addressed by the top 6 fraction bits. Each entry stores the value at the **midpoint** of its bin, which halves the worst-case error.
   - 2^(−⌊u⌋): a right shift. If ⌊u⌋ ≥ 16 the result is flushed to 0, since it would be < 1 LSB.
4. **Normalization:** Σe is accumulated while the exponentials are written. One sequential restoring divider computes R = ⌊2³²/Σe⌋ in 34 cycles, then each weight is wⱼ = eⱼ·R ≫ 16. This replaces **N divisions with 1 division + N multiplies** on the existing MAC.

**LUT size vs. accuracy** (worst-case relative error of 2^(−u), measured exhaustively):

| LUT entries | 8 | 16 | 32 | **64 (chosen)** | 256 |
|---|---|---|---|---|---|
| Worst rel. error | 4.29 % | 2.21 % | 1.17 % | **0.62 %** | 0.23 % |

The 64×16-bit ROM is 128 bytes. Quadrupling it to 256 entries reduces the error only 2.7×.

Alternatives considered: a piecewise-linear exp (no ROM, about 6 % error), CORDIC (accurate but iterative and slow), a pure base-2 softmax (removes the log₂e multiply but changes the function), a combinational divider (large, and it limits Fmax, for a computation done once per row), and online softmax (streaming max/sum, which would also allow processing K/V in blocks).

## 7. Verification and results

**Methodology.** Verification has three levels:
1. **Bit-exact:** `fixed_model.py` mirrors every integer operation of the RTL. `check.py` compares all intermediate buffers (Q, K, V, S, weights) and the output, and requires 0 mismatches. This proves the RTL is correct.
2. **Accuracy:** the hardware output is compared with float NumPy. This measures the cost of the design choices.
3. **Sanity:** softmax row sums are checked to be ≈ 1, and the measured latency must equal the analytic formula.

The checker itself was validated by injecting an error into an output file, which it reported as a failure.

**Unit tests**
- `tb_mac`: 200 random dot products (lengths 1–64, including the worst-case operands) and 5000 rounding/saturation cases, checked against an independent real-number formula. **PASS**
- `tb_exp_div`: the exp unit **exhaustively** over all 65 536 inputs against the real 2^(−u/256) within the analytic error bound, and the divider on edge cases plus 300 random divisors against integer division. **PASS**

**System tests** (`results/summary.md`)

**Hand-worked example (`hand2`).** X = [[1,0,1,0],[0,2,0,2]], with W_Q and W_K = 0.5 × permutation-like 0/1 matrices and W_V = I:

| | Float (by hand / NumPy) | Hardware |
|---|---|---|
| Scaled scores | [[0.25, 1.5], [1.5, 1.0]] | [[64, 384], [384, 256]] / 256: **exact** |

## 8. Performance and trade-offs

**Latency** (cycle-exact, matched in every test):
```
cycles = 3·N·dₖ·(D+1)                                   projections
       + N·[ N·(dₖ+1) + 4N + 35 + dₖ·(N+1) ]            per row: scores, exp, divide, normalize, output
       + 1
```
The useful multiply count is 3·N·D·dₖ + 2·N²·dₖ + 2N². For N = 16 and dₖ = 64 the utilization is 229,888 / 235,313 = **97.7 %**.

| Trade-off | This design | Possible direction |
|---|---|---|
| Throughput vs. area | 1 MAC, ≈ 1 multiply/cycle | P parallel MACs on the column loop (≈ P×), or a systolic array for the matrix products |
| Fmax vs. simplicity | Single-cycle 18×18 multiply + 48-bit add | 2–3 stage pipelined MAC |
| Precision vs. cost | Q8.8 / 64-entry LUT | Q4.12 for weights or per-tensor scaling for larger models; a larger LUT or linear interpolation |
| Memory | Combinational-read buffers, which map to registers/LUTRAM | Synchronous reads with prefetch, which infer block RAM (M9K) |
| Phase overlap | Phases strictly serial | Run the divider for row i while computing the scores of row i+1; overlap the projections with the scores |
| Score storage | O(N) (row streaming) | Block-wise online softmax (FlashAttention style) so K/V can also stream from off-chip memory |

**Limitations:** dₖ must be a power of 4; there is a single head with no masking; inputs and intermediates must fit in Q8.8 (±128), and the test generator reports any saturation (0 in all tests).

## 9. Possible extensions
- Synthesis for an Intel Cyclone IV (RZ-EasyFPGA A2.2) in Quartus, with resource and Fmax reporting
- A parameterizable number of parallel MACs
- Causal masking (skip j > i), which also halves the score work
- Multi-head support by time-multiplexing heads through the same datapath
